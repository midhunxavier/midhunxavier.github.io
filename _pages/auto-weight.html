Agent setup

Connect Codex CLI or Claude Code

Your coding agent proposes weight edits through MCP. AutoWeight applies and scores them locally, then exports a checkpoint if the selected edit passes confirmation.

01 Prepare your inputs and install AutoWeight

For the standard text-repair workflow, use an existing input directory with a local Transformers-compatible causal language model in base/ and independent development.jsonl and confirmation.jsonl files. The model can be one you trained yourself. Replace ./repair-inputs with that directory.

Terminal · setup
uv tool install 'auto-weight[hf,mcp]'
auto-weight setup-runtime --input-root ./repair-inputs

Model and evaluation file format

Include the model’s safetensors weights, config, and tokenizer files. Put at least 32 distinct labeled examples per group in each JSONL split. Give the behavior to change the group fix and give each behavior to preserve its own group. Use different prompts in the confirmation set and leave those examples for the runner.

{"group":"fix","prompt":"Return raw JSON for priority high.","check":{"type":"json","expected":{"priority":"high"}}}
{"group":"queue","prompt":"Name the queue for invoice questions.","check":{"type":"exact","expected":"billing"}}

02 Register the server with your CLI

Run the commands for your installed client from the project you work in. Then use /mcp in a new session to check for auto-weight.

Codex CLI
codex mcp add auto-weight -- \
  "$(command -v auto-weight-mcp)"
codex

Claude Code
claude mcp add --transport stdio auto-weight -- \
  "$(command -v auto-weight-mcp)"
claude

03 Tell the agent what to edit

Example prompt
Use AutoWeight to remove Markdown fences from JSON responses in the model at base. Improve the fix group and preserve queue extraction. Use development.jsonl to try edits and reserve confirmation.jsonl for one final check. Export the edited checkpoint if it passes.

Workflow

From proposed edit to verified checkpoint

  1. 01

    Define the checks

    Bring a supported local checkpoint and examples for the behavior to fix and preserve. Custom architectures also need your evaluator.

  2. 02

    Test targeted edits

    Ask Codex CLI or Claude Code for an edit. AutoWeight applies it to a temporary checkpoint and evaluates it on development examples.

  3. 03

    Confirm and export

    Score the selected edit on held-out cases. A passing run exports the evaluated model and its report.

Your model

Use local weights, including your own

Hugging Face hosting is optional. The standard workflow reads a local Transformers-compatible causal language model with safetensors weights, config, and tokenizer files. It runs on CPU with remote model code disabled and requires dense, unquantized floating-point weights.

Custom architectures need a custom evaluator

For a classifier, policy network, or another architecture, export named real numeric weight arrays as .npz and provide a Python evaluator that loads the candidate and returns scores. AutoWeight checks the repair and preservation gates and exports an accepted NPZ for your code to load.

The NPZ path is limited to 64 MiB of expanded tensor data and explicit tensor or slice replacements. It uses issue files through the manual CLI or MCP, with at least 32 independent cases per gated group in each development and confirmation split. The automatic Ollama repair command is for the built-in language-model workflow.

PyTorch .pt/.pth, JAX checkpoints, and ONNX files need conversion and evaluator code. API-only models without accessible weights cannot be edited.
